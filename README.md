# Central
# 一个小型操作系统内核
## 目录结构
|目录|描述|
|:-:|:-|
|apps|存放系统应用和用户应用代码|
|arch|存放跟CPU架构相关的移植代码|
|board|存放开发板的驱动代码|
|core|内核核心代码|
|soc|存放跟SOC芯片相关的移植代码和驱动代码|
|third|存放第三方开源代码|
|user|存放用户通用代码|
## 移植到你的开发板上
1. 在arch上增加你的CPU架构移植代码
2. 在soc上增加你的SOC移植代码和驱动代码
3. 在board上增加你的开发板驱动代码
4. 和core代码一起编译，其它apps、user、third是可选项
## 开始启动
```C
#include "central.h"
#include "sys_task.h"
int main()
{
    sys_init();                   //全局初始化
    sys_task_add_cpu_thread();    //添加CPU
    ...
    ...
    ...
    sys_task_start();             //开始任务调度
    return 0;
}
```
## 内存管理
内存管理算法支持分配内存页（使用sys_alloc_pages函数）和分配任意大小的内存（使用sys_malloc函数），不必太过忧虑内存碎片的产生，算法会自动整合碎片。
## 任务调度
用户可以创建两种任务，分别是实时任务，使用sys_task_create_rt创建，优先级范围是0-63，数字越小优先级越高，高优先级任务始终占有CPU，同优先级任务轮流占有CPU；普通任务，使用sys_task_create创建，优先级范围是0-39，数字越小优先级越高，高优先级任务获得更多的CPU执行时间，每高一级获得多百分之十的运行时间，如果有就绪的实时任务，始终是实时任务先执行。
## SMP
内核支持对称多核、或者多物理线程，不同的核或物理线程被认为对内存或IO设备的的访问权限是一样的，但允许不同的核或物理线程的处理能力不一样，在sys_cpu_info_t的ability字段可以描述不同的核或物理线程的处理能力，以100为基准，高百分之20为120，低百分之20为80；任务可以在不同的核或者物理线程中迁移，但是实时任务和普通任务的迁移策略不一样，实时任务注重保障高优先级任务得到先执行的机会，普通任务注重不同核心或者物理线程的负载均衡。
## 任务间的通信
内核提供了信号量sys_semaphore_t和消息队列sys_msg_queue_t来支持任务间的通信问题，其中sys_msg_queue_t是一个先进先出的数据结构，在没有数据的情况下接收端会阻塞等待。
## 互斥与同步
用户可以使用原子变量sys_atomic_t（依赖于硬件指令实现）来保证数据的同步，对于更加复杂的数据结构，可以使用锁进行代码段互斥，内核提供了多种锁，分别有互斥锁sys_mutex_t、递归互斥锁sys_recursive_mutex_t、读写锁sys_rwlock_t和自旋锁sys_spin_lock_t，用户可以根据不同的场景选用不同的锁，在不允许睡眠的中断和软中断上下文中，只能使用自旋锁。
## 定时器
定时器sys_timer_t提供一个定时调用服务函数的功能，其运行在定时器任务中，定时器任务是一个实时任务，故在服务函数中可以当作在实时任务中那样使用各类可以引起任务睡眠的函数。
## tasklet
tasklet是一个中断下半部的概念，其服务函数运行在软中断上下文中，每个tasklet的服务函数只会在一个CPU核或者物理线程中执行，跟中断一样，在tasklet服务函数中不允许调用任何会引起任务睡眠或挂起的函数，只能使用自旋锁sys_spin_lock_t进行数据保护，如果一定要用延时，可以用延时函数sys_task_ndelay，但sys_task_ndelay会影响其他tasklet服务函数的响应和浪费CPU资源。
## 虚拟文件系统
虚拟文件系统VFS是一套代码框架，用于给其他文件系统（如LFS、FATFS）提供统一的操作接口，并且可以让多个文件系统根目录都挂在在同一棵目录树的不同节点上。
## 设备文件系统
设备文件系统devfs是一套通用的驱动框架，用于让驱动程序和设备进行分离，并且通过文件系统接口的方式去访问设备。
